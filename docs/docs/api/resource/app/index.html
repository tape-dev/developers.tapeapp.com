App

Use these endpoints to create, read, update and delete the apps of a workspace.

An app belongs to exactly one workspace. A database app holds records of one kind. To find an app by name across all workspaces, use the Search resource.

Which capability do I need?

Endpoints that read apps need apps:read. Endpoints that change apps need apps:edit. See Capabilities.

Where do I find the app ID and field IDs?

In Tape, open the app menu (Follow, export and more…) and select Developer. It shows the Workspace ID, the App ID and, for each field, its Field ID and External ID (the field's slug). Through the API, Retrieve all available apps returns every app_id, and Retrieve a single app returns the field_id and slug of every field.

The field object​

Each entry in fields describes one field. The format of config.settings depends on the field type. See Fields.

PropertyTypeDescriptionExample value
field_idnumberThe field ID.1
slugstringSlug of the field, unique in its app. Use it as a key in the fields of a record."name"
external_idstringDeprecated. Same as slug."name"
labelstringName of the field."Name"
field_typestringThe field type. It tells single and multi fields apart, for example single_category and multi_category."single_text"
typestringThe data type, the same for single and multi fields. Prefer field_type."text"
config.labelstringSame as label."Name"
config.slugstringSame as slug."name"
config.external_idstringDeprecated. Same as slug."name"
config.descriptionstringHelp text of the field. Missing when the field has none."The full name of the contact."
config.show_descriptionbooleantrue if records show the help text. A new single_text or multi_text field with a description gets true, a new field of another type gets false. For updates, see Fields.true
config.requiredbooleantrue if every record needs a value.true
config.always_hiddenbooleantrue if every record hides the field.false
config.hidden_if_emptybooleantrue if records hide the field while it has no value.false
config.primarybooleantrue for the primary field. Its value names each record. Some database apps have no primary field.true
config.settingsobjectSettings of the field type.{ "formatted": false, "format": "plain" }

Retrieve apps for a workspace​

Use this endpoint to list all apps of one workspace.

GEThttps://api.tapeapp.com/v1/app/workspace/{workspace_id}
Request
curl https://api.tapeapp.com/v1/app/workspace/200 \
  -H "Authorization: Bearer $TAPE_TOKEN"
Response
{
  "total": 2,
  "apps": [
    {
      "app_id": 1,
      "workspace_id": 200,
      "name": "Tasks",
      "record_name": "Task",
      "slug": "tasks",
      "type": "database",
      "config": {
        "item_name": "Task",
        "name": "Tasks"
      }
    },
    {
      "app_id": 2,
      "workspace_id": 200,
      "name": "Projects",
      "record_name": "Project",
      "slug": "projects",
      "type": "database",
      "config": {
        "item_name": "Project",
        "name": "Projects"
      }
    }

}

The example lists the apps of the workspace with ID 200, without their fields. To read the fields, retrieve the app by its ID.

Requirements: apps:read. Works with a personal access token, an OAuth access token or a user API key.

General behavior

  • Tape creates the fields in the order of the fields array.
  • Set the record name with item_name. The response returns it as record_name.
  • Without position, the new app goes after the last app of the workspace.
Workspace has 500 apps?

A workspace holds at most 500 apps. Further create requests then return an error. Delete an existing app to create a new one.

Requirements: apps:edit, and a workspace role that may edit apps in the workspace. Works with a personal access token, an OAuth access token or a user API key.

General behavior

  • Send only the properties you want to change.
  • A field in fields with a field_id updates that existing field. A field without field_id creates a new field. Tape adds new fields after the existing ones, in the order of the array.
  • To delete a field, add it to fields_to_delete with its field_id. This also deletes its values in every record. Entries copied from the app's fields property work too.
  • Fields that are in neither array stay unchanged.
  • To delete options of a category or status field, send options_to_delete in the config.settings of that field. See Category and Status.
  • Want to make sure a request never deletes anything? Set reject_deletions to true.

Requirements: apps:edit, and Full access to the app. Works with a personal access token, an OAuth access token or a user API key.

Errors

With reject_deletions=true, a request that deletes a field (fields_to_delete) or an option (options_to_delete) returns 400 with deletions_rejected. Tape applies nothing from that request, not even the other changes in the body:

{
  "status_code": 400,
  "endpoint": "/v1/app/1",
  "error_code": "deletions_rejected",
  "error_message": "This request asks for something to be deleted ('fields_to_delete' names 1 field(s)), and it was sent with 'reject_deletions=true'. Nothing was applied — not the deletions, and not the rest of the body. Remove the deletion from the request, or send it without 'reject_deletions'."
}

Query parameters

ParameterTypeDescription
reject_deletionsbooleanReject the request with 400 (deletions_rejected) if it deletes a field (fields_to_delete) or an option (options_to_delete). Nothing is applied then (default: false).

Delete an app​

Use this endpoint to delete an app.

DELETEhttps://api.tapeapp.com/v1/app/{app_id}
Can you undo deleting an app?

No. Deleting an app also deletes all its records and fields.

  • cURL
Request
curl -X DELETE https://api.tapeapp.com/v1/app/1 \
  -H "Authorization: Bearer $TAPE_TOKEN"
Response
{
  "app_id": 1
}

Requirements: apps:edit, and Full access to the app. Works with a personal access token, an OAuth access token or a user API key.
