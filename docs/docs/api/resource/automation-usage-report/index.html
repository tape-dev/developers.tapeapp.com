Use this endpoint to see how many actions and automation runs your organization used, per hour, day, week, month or year.

The report covers the organization of your credential. You can't read the usage of another organization.

Retrieve an automation usage report​

Use this endpoint to get usage buckets for your organization, newest first.

GET/v1/automation-usage-reportapi.tapeapp.com

curl -G https://api.tapeapp.com/v1/automation-usage-report \

The example requests the 30 most recent daily buckets.

The response has no bucket for 2024-01-16, because nothing ran that day.

General behavior

  • Buckets come newest first (by bucket start), up to limit.
  • Tape returns only buckets with activity. Periods without activity don't appear as empty buckets.
  • Bucket boundaries follow the calendar in UTC. weekly uses the ISO week: a week starts on Monday at 00:00 UTC.
  • A personal access token limited to some apps still returns the totals of the whole organization. The report has no per-app breakdown.
Don't see the latest activity?

A background job builds the report from regular snapshots. The newest bucket can lag behind live activity until the job runs again. Use the endpoint for usage history, not for live metering.

Requirements: automations:read. Works with a personal access token, an OAuth access token, a user API key or an automation API key.

Errors

A missing, out-of-range or non-integer limit, or an unknown interval_resolution, returns 400 with validation. For example, limit=250 returns:

Response
{
  "status_code": 400,
  "endpoint": "/v1/automation-usage-report",
  "error_code": "validation",
  "error_message": "Query param \"limit\" must be between 0 and 100, got 250."
}

See Errors for all error codes.

Query parameters

limitintegerrequired

Number of buckets to return, from 0 to 100. 0 returns an empty list.

interval_resolutionstringrequired

Size of a bucket. One of hourly, daily, weekly, monthly or yearly.

ParameterTypeRequiredDescription
limitintegerYesNumber of buckets to return, from 0 to 100. 0 returns an empty list.
interval_resolutionstringYesSize of a bucket. One of hourly, daily, weekly, monthly or yearly.

Response fields

Each entry in usage_reports describes one time bucket:

organization_idinteger

The organization of the report.

Example value 1337

fromstring

Start of the earliest reporting interval with activity in the bucket, in UTC (YYYY-MM-DD HH:mm:ss). Can be later than the start of the calendar bucket.

Example value "2024-01-18 08:12:04"

from_utcstring

Same value as from, in UTC.

Example value "2024-01-18 08:12:04"

tostring

End of the latest reporting interval with activity in the bucket, in UTC (YYYY-MM-DD HH:mm:ss). Can be earlier or later than the end of the calendar bucket.

Example value "2024-01-18 22:47:51"

to_utcstring

Same value as to, in UTC.

Example value "2024-01-18 22:47:51"

num_consumed_actionsinteger

Action credits consumed in the bucket.

Example value 320

num_succeeded_runsinteger

Automation runs that finished successfully (status completed).

Example value 540

num_failed_runsinteger

Automation runs that finished with a failed status.

Example value 12

num_cancelled_runsinteger

Automation runs that finished with a cancelled status.

The top-level organization_id repeats the organization of every bucket. from and to stay in UTC, unlike most dates in the API, because they define the UTC buckets. They use the format described in Date & timezone: no T separator, no Z suffix, no milliseconds.

Rate limit credits​

Each request to this endpoint costs 2x the base credits. See Request limits for how credits work.
