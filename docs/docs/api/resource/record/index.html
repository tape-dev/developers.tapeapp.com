Use these endpoints to create, read, update, delete and restore the records of a database app.

To find records by text across all apps, use the Search resource.

In the Podio API, a record is an item: record_id replaces item_id, and app_record_id replaces app_item_id.

Which capability do I need?

Endpoints that read records need records:read. Endpoints that change records need records:edit. See Capabilities.

The example is shortened: it leaves out app.config and revisions. It comes from a user whose timezone is one hour ahead of UTC.

List endpoints, such as Retrieve records for an app, return the same object without revisions and with comment_count.

record_idnumber

The record ID. Unique across all apps.

Example value 1

app_record_idnumber

The running number of the record in its database app.

Example value 1

record_urlstring

Link to the record in Tape.

Example value "https://tapeapp.com/acme/record/1"

app_idnumber

The database app the record belongs to.

Example value 1

appobject

Preview of the database app: app_id, name, record_name, workspace_id, workspace, icon, plus a legacy config copy of all of them except app_id.

Example value { "app_id": 1, "name": "Contacts", … }

titlestring

The computed title of the record. May be missing.

Example value "Clara Weber"

created_onstring | null

When the record was created, as YYYY-MM-DD HH:mm:ss in your timezone. See Date & timezone.

Example value "2022-03-01 12:00:00"

created_on_utcstring | null

The same moment as created_on, in UTC.

Example value "2022-03-01 11:00:00"

last_modified_onstring | null

When the record last changed, in your timezone.

Example value "2022-03-02 09:30:00"

last_modified_on_utcstring | null

The same moment as last_modified_on, in UTC.

Example value "2022-03-02 08:30:00"

deleted_onstring | null

When the record was deleted, in your timezone. null unless the record is in the trash.

Example value null

deleted_on_utcstring | null

The same moment as deleted_on, in UTC.

Example value null

created_byobject | null

The author who created the record. See Authors.

Example value { "type": "user", "id": 600, … }

last_modified_byobject | null

The author who last changed the record. See Authors.

Example value { "type": "user", "id": 600, … }

fieldsarray

The field values of the record. A field without a value isn't listed. See Field values.

Example value [{ "field_id": 1, "values": [ … ] }]

current_revisionobject | null

The latest revision of the record. See Record revision.

Example value { "type": "update", "revision": 1, … }

initial_revisionobject | null

The first revision of the record.

Example value { "type": "creation", "revision": 0, … }

revisionsarray

The latest revisions of the record. Only in responses about one record. To read all revisions, use Record revision.

Example value [{ "type": "update", … }]

comment_countnumber

Number of comments on the record, without replies. Only in list responses.

Authors​

created_by and last_modified_by hold one of three kinds of author. Check type to know which one you have.

"user"

A user. user_id is the same as id.

Properties id, user_id, org_id, mail, email, name, and phone if set

"workflow"

An automation. automation_id is the same as id. workflow_id is deprecated.

Properties id, automation_id, workflow_id, mail, name

"share_session"

A visitor who changed the record through a share link. Only in last_modified_by. share_session_id is a UUID string, mail is empty, and name is a generated label that isn't unique.

Prefer the API? Retrieve all available apps returns every app_id. Retrieve a single app returns every field with its field_id and slug. Both need apps:read.

Don't see Developer?

You need Full access to the app.

  -H "Authorization: Bearer $TAPE_TOKEN"
Response

  "result": 3,
  "source_record_id": 1,
  "target_field_id": 12

The example sums up the number field 12 over all records related to record 1.

General behavior

  • The endpoint looks at every record of the field's app that is related to record_id, through incoming or outgoing relations.
  • It aggregates the field field_id over these records.

Requirements: records:read, and view access to the record and to the field's app. Works with a personal access token, an OAuth access token, a user API key or an automation API key.

Query parameters

aggregation_typestring

One of COUNT (default), COUNT_NOT_EMPTY, COUNT_EMPTY, PERCENT_EMPTY, PERCENT_NOT_EMPTY, SUM, AVG, MEDIAN, MIN or MAX.

ParameterTypeDescription

SUM, AVG, MEDIAN, MIN and MAX work only on number fields and on calculation fields that return a number.

General behavior

  • The endpoint returns at most 1000 records. It has no pagination.

  • An unknown direction returns no records instead of an error. Use forward, reverse or both.

Requirements: records:read. Works with a personal access token, an OAuth access token, a user API key or an automation API key.
