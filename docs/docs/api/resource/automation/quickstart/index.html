Automation API

Automation API quickstart

Use this quickstart to build your first automation through the API, from the catalog to a finished run.

You go through the full lifecycle: discover → create → configure → validate → activate → run → observe. The example builds an automation that sends an email when a new high-priority lead comes in.

Only want to start an automation that already exists? Skip this guide and see Run an existing automation.

Requirements

  • A personal access token with the capabilities Read automations, Edit automations and Run automations (automations:read, automations:edit and automations:run). Store it in the variable TAPE_TOKEN. A user API key or an OAuth access token works too.
  • The Admin role in the app's workspace. The token's content access must include the app.

Step 1: Discover the vocabulary​

Read which triggers, actions and filter operators exist. Don't hard-code them.

Request
curl https://api.tapeapp.com/v1/automation/meta/trigger \
  -H "Authorization: Bearer $TAPE_TOKEN"

Do the same for /meta/action and /meta/filter?field_type=number. Trigger and action entries have a config_schema to build against. A /meta/filter entry is an operator, { operator, label, description?, value_arity }, without one.

Step 2: Create the automation​

Create the automation in an app. A new automation starts paused and not broken: a draft that you finish and then activate.

Request
curl -X POST https://api.tapeapp.com/v1/automation/app/87 \
  -H "Authorization: Bearer $TAPE_TOKEN" \
  -H "Content-Type: application/json" \
  --data '{
    "name": "Email the owner on a new high-priority lead",
    "trigger": { "type": "record_created", "config": {} }
  }'

Replace 87 with the ID of your app. Retrieve all available apps lists the app IDs.

The response is the automation object, wrapped as { "automation": … }. Keep its id for the next steps.

Step 3: Configure the filter and actions​

Add a filter and actions with a partial update. Fields you leave out stay unchanged.

Request
curl -X PUT https://api.tapeapp.com/v1/automation/4021 \
  -H "Authorization: Bearer $TAPE_TOKEN" \
  -H "Content-Type: application/json" \
  --data '{
    "filter": {
      "operator": "and",
      "rows": [
        {
          "subject": { "kind": "variable", "source": "field", "field_id": 512, "field_type": "single_category", "previous": false, "collection": false, "triggering": false },
          "operator": "is_any_of",
          "value": { "type": "ids", "ids": [9001] }
        }
      ]
    },
    "actions": [
      { "type": "send_email", "config": { "to_address": ["juliet@acme.com"], "subject": ["A new high-priority lead was created"] } }
    ]
  }'

Replace 4021 with the id from step 2, 512 with a category field of your app and 9001 with the ID of one of its options. Retrieve a single app returns the field_id and, in config.settings.options, the option IDs. To send the email for every new record, leave out filter.

Node IDs are optional: Tape creates them when you leave them out. The field reference in subject is a dynamic value that pulls in live record data.

Step 4: Validate​

Check the definition before it goes live. Create and update don't store a new verdict, so broken can lag behind your edit.

Request
curl https://api.tapeapp.com/v1/automation/4021/validate \
  -H "Authorization: Bearer $TAPE_TOKEN"

{ "valid": true, "errors": [] } means it's ready. Otherwise each entry names the fault. See Errors & broken reasons.

Step 5: Activate​

Set the automation live. Tape checks the definition again and refuses a broken one with 409.

Request
curl -X POST https://api.tapeapp.com/v1/automation/4021/activate \
  -H "Authorization: Bearer $TAPE_TOKEN"

From now on, every new record that matches the filter fires the automation. Pause it when you finish testing.

Step 6: Run and observe​

Run the automation manually on a record, then poll for the result. A manual run has real side effects. It runs asynchronously: the response is 202 with a message and no run ID.

Request
curl -X POST https://api.tapeapp.com/v1/automation/4021/manual-run \
  -H "Authorization: Bearer $TAPE_TOKEN" \
  -H "Content-Type: application/json" \
  --data '{ "record_id": 5001 }'

Replace 5001 with the ID of a record in the automation's app that matches the filter. A record that doesn't match creates no run. Retrieve records for an app lists the record IDs. Then list the automation's runs and find the one with your triggered_on_record_id:

Request
curl -X POST https://api.tapeapp.com/v1/automation-run/automation/4021 \
  -H "Authorization: Bearer $TAPE_TOKEN" \
  -H "Content-Type: application/json" \
  --data '{ "limit": 5 }'

Its status ends as completed, failed or cancelled. See List runs for an automation for the response, and Run & simulate for the run body per trigger and the polling model.

A failed run names the cause in failure_reason and error_message. Retrieve the run by its id to read the step logs.

Want to test without sending the email?

Send the same request to /v1/automation/4021/simulate instead of /manual-run. Tape creates a run with type: "simulation" and no side effects. Its filter step reads skipped. The email step reads success, and its log message says that Tape skipped the email because of the simulation. See Simulate an automation.
