Tape API

Errors

Use the HTTP status and the error_code of a response to find out why a request failed.

This is the response for a record that doesn't exist:

{
  "status_code": 404,
  "endpoint": "/v1/record/123",
  "error_code": "record_not_exists",
  "error_message": "Record does not exist(123)!"
}

The HTTP status gives the class of the error. The response body adds detail in error_code and error_message.

Error codes​

Statuserror_codeDescription
400validationThe request is not valid: the body is not valid JSON, doesn't match the expected parameters, or the credential is invalid, malformed or can't be used for this endpoint. Check the error_message property for details.
400input_validationThe body doesn't match the endpoint's schema. error_message starts with Invalid input: and names each property that fails, for example data/name must NOT have fewer than 1 characters.
400bad_requestThe request is malformed, for example an empty records array in a batch request.
400record_no_permission / app_no_permissionThe user has no permission for this record or app.
400record_deletedThe record is in the trash.
400workspace_invalid_permissionThe user has no permission for this workspace, for example no Admin role in it.
400deletions_rejectedThe request was sent with reject_deletions=true and would delete a field or an option. Tape applies nothing from the request. See Update an app.
401dev_api_authenticationThe request carries no personal access token, OAuth access token or user API key.
401unauthorizedThe credential type isn't accepted for this endpoint (for example an automation API key on an endpoint that needs a credential acting for a user), or the user may not perform this operation. error_message says why.
401dev_api_invalid_access_tokenThe OAuth access token is expired, revoked or otherwise no longer valid. Refresh it, or connect again. See OAuth errors.
403forbiddenThe request is not allowed. If the response carries WWW-Authenticate: Bearer error="insufficient_scope", the personal access token or OAuth access token lacks a capability this endpoint requires. See Insufficient capabilities. Otherwise the operation was refused for another reason, such as the user's permissions; error_message says why.
404not_foundThe resource doesn't exist, isn't shared with the owner of the credential, or lies outside a personal access token's content access. An unknown path, or a method a path doesn't support, also returns not_found (for example Cannot GET /v1/recrods).
404record_not_existsThe requested record doesn't exist.
404app_not_existsThe requested app doesn't exist.
409conflictThe resource is in a state that doesn't allow this operation, for example activating or running a broken automation.
429user_too_many_requestsThis request exceeds the number of requests allowed. Wait the seconds in the Retry-After header, then retry. See rate limits.
500unknownAn unexpected error occurred. Reach out to Tape support.

General behavior​

  • Endpoints can return other, more specific error_code values. Handle an unknown error_code by its HTTP status.
  • A missing permission on a record or app returns 400, not 403. Check error_code to tell it apart from other 400 errors.
  • A request body that isn't valid JSON returns 400 with validation. The message starts with "A valid JSON body is required for operation".
Getting an error?

403 error

Check the WWW-Authenticate header. With insufficient_scope, fix the missing capability: create a new token, or ask the user of an OAuth app to approve it. Without that header, the user's own permissions in Tape refuse the request.
