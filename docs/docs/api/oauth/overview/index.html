OAuth

Tape is an OAuth 2.1 authorization server. Your app sends a user to Tape, the user signs in and approves what your app asked for, and your app receives an access token that calls the Developer API and the Tape MCP server as that user. The user never copies a secret into your app, and can disconnect it at any time.

When to use OAuth​

OAuth is mainly for MCP clients and for integrations and partners registered by Tape. If you are a developer calling the API directly — for yourself, or to act in Tape on a user's behalf — use a personal access token instead. It needs no client registration, no redirect and no consent screen.

You are buildingUse
A script, internal tool or integration that calls the API directly, including on a user's behalfA personal access token
An MCP client or AI platformOAuth, with a client that registers itself
An integration or partner product with a "Connect to Tape" or "Sign in with Tape" buttonOAuth, with a client registered by Tape — see the integration guide

A personal access token can do everything an OAuth token can and more: it can be limited to selected workspaces and apps, and it needs no refreshing. See Which credential to use.

How it works​

  1. Your app sends the user's browser to Tape's authorization endpoint, naming the scopes it needs.
  2. The user signs in to Tape if they are not already, chooses the organization to connect, and sees the consent screen: your app's name and what it will be able to do.
  3. When the user approves, Tape redirects the browser back to your app with a short-lived authorization code.
  4. Your app exchanges the code at the token endpoint for an access token and a refresh token.
  5. Your app calls the API with the access token. The access token lasts one hour; the refresh token gets a new one.

Each approval creates a connection between the user and your app. A connection keeps working until the user, an organization admin or your app disconnects it, or the user loses access to the organization. It also expires after 90 days without a refresh and — unless Tape registered your client as a confidential one — 365 days after the user approved it. The authorization flow walks through every step.

Supported flows​

Grant typeSupported
Authorization code with PKCE (authorization_code)Yes — the only way to obtain a token
Refresh token (refresh_token)Yes
Client credentialsNo
Device authorizationNo
Implicit, resource owner passwordNo — both are removed in OAuth 2.1
  • PKCE is required, with the S256 method. plain is refused.
  • The response type is code and the response mode is query.
  • Tape is not an OpenID Connect provider. There is no id_token and no OpenID userinfo endpoint. The token response names the user (tape_user_id), and GET /v1/user returns the rest.
  • Tokens are opaque. They are not JWTs; do not try to decode them.

Endpoints​

The issuer is https://api.tapeapp.com.

EndpointURL
Authorization server metadata (RFC 8414)GET https://api.tapeapp.com/.well-known/oauth-authorization-server
AuthorizationGET https://api.tapeapp.com/oauth/authorize
TokenPOST https://api.tapeapp.com/oauth/token
Revocation (RFC 7009)POST https://api.tapeapp.com/oauth/revoke
Dynamic client registration (RFC 7591)POST https://api.tapeapp.com/oauth/register
Protected resource metadata — Developer APIGET https://api.tapeapp.com/.well-known/oauth-protected-resource/v1
Protected resource metadata — Tape MCPGET https://mcp.tapeapp.com/.well-known/oauth-protected-resource/mcp

The authorization server metadata also lists an introspection endpoint. It is reserved for Tape's own services and refuses every other client.

The token and revocation endpoints take application/x-www-form-urlencoded bodies; registration takes application/json. Send each parameter at most once — only resource may repeat. The token, revocation and registration endpoints and all three metadata documents allow cross-origin requests, so an app running in a browser can call them.

Prefer discovering the endpoints from the metadata over hard-coding them:

GET https://api.tapeapp.com/.well-known/oauth-authorization-server
{
  "issuer": "https://api.tapeapp.com",
  "authorization_endpoint": "https://api.tapeapp.com/oauth/authorize",
  "token_endpoint": "https://api.tapeapp.com/oauth/token",
  "revocation_endpoint": "https://api.tapeapp.com/oauth/revoke",
  "introspection_endpoint": "https://api.tapeapp.com/oauth/introspect",
  "registration_endpoint": "https://api.tapeapp.com/oauth/register",
  "scopes_supported": ["apps:read", "records:read"],
  "response_types_supported": ["code"],
  "response_modes_supported": ["query"],
  "grant_types_supported": ["authorization_code", "refresh_token"],
  "token_endpoint_auth_methods_supported": ["client_secret_basic", "client_secret_post", "none"],
  "revocation_endpoint_auth_methods_supported": ["client_secret_basic", "client_secret_post", "none"],
  "introspection_endpoint_auth_methods_supported": ["client_secret_basic", "client_secret_post"],
  "code_challenge_methods_supported": ["S256"],
  "client_id_metadata_document_supported": true,
  "authorization_response_iss_parameter_supported": true,
  "service_documentation": "https://developers.tapeapp.com/oauth"
}

scopes_supported lists only the default read scopes. Every scope in Capabilities and Scopes can be requested.

What an access token can do​

  • It acts as the user. Its access is the user's own permissions, narrowed by the scopes they approved. Records it creates or changes show the user as the author.
  • It reaches everything the user can. Unlike a personal access token, an OAuth access token cannot be limited to selected workspaces and apps.
  • It works at the Developer API and the MCP server alike. One token is valid at https://api.tapeapp.com/v1 and at https://mcp.tapeapp.com/mcp.
  • It shares the user's rate limit. Every connected app draws from the same per-user budget as the user's personal access tokens. See Request limits.

Send it as a bearer token, exactly like a personal access token:

curl https://api.tapeapp.com/v1/user \
  -H "Authorization: Bearer tape_oat_0a1b2c3d..."

Credential formats​

Every OAuth credential has a recognizable prefix. The prefix is part of the value: store and send each one verbatim.

CredentialPrefixLifetime
Access tokentape_oat_1 hour
Refresh tokentape_ort_Public client: single use, each refresh returns a new one. Confidential client: as long as its connection. See Refreshing
Authorization codetape_oac_60 seconds, single use
Client IDtape_oc_— (a metadata document client uses its URL instead)
Client secrettape_ocs_Until Tape rotates it
