Tape MCP

Build an MCP client for Tape

Use this page to build an MCP client that connects to Tape, or to add Tape support to an existing client.

Tape follows the MCP authorization specification. A client that implements it connects without anything specific to Tape.

Requirements at a glance​

RequirementWhat Tape uses
Endpointhttps://mcp.tapeapp.com/mcp
TransportStreamable HTTP: JSON-RPC 2.0 over POST. There is no SSE endpoint
AuthorizationOAuth 2.1 authorization code flow with PKCE (S256), the only supported flow
DiscoveryProtected resource metadata (RFC 9728), then authorization server metadata (RFC 8414)
Client registrationA client ID metadata document or dynamic client registration (RFC 7591)
CredentialA bearer access token on every request, renewed with a refresh token

How a client connects​

  1. Discover. Without a token, Tape answers initialize and every tool call with 401 and points to its protected resource metadata. Only tools/list, resources/* and ping work without a token. The metadata names Tape's authorization server and the scopes the Tape MCP tools use.
  2. Register as a public client. See Register a client yourself.
  3. Authorize with PKCE and request the scopes from the protected resource metadata. The user signs in to Tape and approves. See the authorization flow.
  4. Call tools with the access token, and refresh it when it expires.
  5. Step up when a tool needs a scope the connection lacks. Tape answers 403 and names the scopes to request. See Asking for more scopes.

Capabilities describes each scope. The same access token also works at the Developer API.

Can't run OAuth in your client?

Send a personal access token as the bearer token instead.
